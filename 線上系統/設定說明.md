# 會員專區（線上系統）設定說明

會員專區網址：`https://taipeihugo.github.io/member/portal/`（官網選單的「會員專區」）。
網頁放在 GitHub Pages；帳號與資料存在 **Supabase**（雲端資料庫，免費方案即可）。

> 會員個資會存在 Supabase 的機房（建議選東京或新加坡）。正式使用前，請先向機關人事或政風單位確認可以這樣做。

## 一、建立 Supabase 專案（約 10 分鐘，只做一次）

1. 到 https://supabase.com 註冊（可用 GitHub 帳號登入）→「New project」。
   - Name：`association`（隨意）
   - Database Password：設一個強密碼，**自己保存好**
   - Region：**Northeast Asia (Tokyo)** 或 Southeast Asia (Singapore)
2. 建好後，左側選單「SQL Editor」→「New query」→ 把 `線上系統/資料庫結構.sql` 全文貼上 → 按「Run」。看到 Success 就完成。
   之後程式更新時，再貼一次最新版全文執行即可，既有資料會保留。
3. 左側「Authentication」→「URL Configuration」：
   - Site URL 填：`https://taipeihugo.github.io/member/portal/`
   - Redirect URLs 加一筆：`https://taipeihugo.github.io/member/portal/`
4. 「Authentication」→「Sign In / Providers」→ Email：確認 **Confirm email** 是開啟的，而且**不要關掉**。
   關掉之後，任何人都能用別人的 Email 註冊，系統無法確認帳號是不是本人的。
5. **設定寄信服務（一定要做，否則會員收不到驗證信）**
   Supabase 內建的寄信服務**只會寄給 Supabase 專案團隊成員的信箱**，而且每小時只能寄 2 封左右。
   不設定的話，同仁用 Gmail 註冊時，畫面會出現「協會尚未完成寄信設定」，忘記密碼也收不到信。
   - 到「Authentication」→「Emails」→「SMTP Settings」（舊版介面在 Project Settings → Authentication → SMTP），開啟 **Enable Custom SMTP**。
   - 最簡單的做法：用協會專用的 Gmail 帳號寄信。
     1. 該 Gmail 帳號要先開啟「兩步驟驗證」，再到 Google 帳戶 → 安全性 →「應用程式密碼」，產生一組 16 碼密碼。
     2. 在 SMTP Settings 填入：
        - Host：`smtp.gmail.com`
        - Port：`587`
        - Username：這個 Gmail 地址
        - Password：上一步的 16 碼應用程式密碼
        - Sender email：同一個 Gmail 地址
        - Sender name：`財政部公務人員協會`
     3. Gmail 一天大約可以寄 500 封，協會規模夠用。會員多、或想用協會網域寄信時，可以改用其他寄信服務（例如 Brevo、Resend 的免費方案），依該服務提供的 SMTP 設定填寫。
   - 設好後到「Authentication」→「Rate Limits」，把 **Rate limit for sending emails** 調高，例如每小時 100 封。推廣期間很多人同時註冊，太低的話後面的人會看到「寄信次數已達上限」。
   - **測試**：用一個**不是** Supabase 團隊成員的 Gmail 到會員專區註冊，確認收得到驗證信。
6. 左側「Project Settings」→「API」（或「Data API」）：複製
   - **Project URL**（像 `https://abcdefgh.supabase.co`）
   - **anon public key**（很長的一串）

   把這兩個值交給開發者，填進 `官網/portal/連線設定.js`；也可以自己在 GitHub 網頁上編輯這個檔案。
   公開金鑰（anon key）本身沒有讀取權限，放在公開網站上是正常的；資料由資料庫的權限規則保護。
   **另一把 `service_role` 金鑰絕對不能給任何人，也不能放在網站上。**

## 二、指定第一位幹部

公務信箱收不到外部信，所以大家都用**個人 Email**（例如 Gmail）註冊。

1. 用你的個人 Email 到會員專區「註冊帳號」，再到信箱點驗證連結。**一定要先註冊**，下一步才能連結。
   如果還沒設定寄信服務、收不到驗證信：在 Supabase「Authentication」→「Users」→「Add user」→「Create new user」，自己建立帳號，並勾選 **Auto Confirm User**。
2. 回到 Supabase 的「SQL Editor」，執行下面這行（依序是：個人 Email、角色、姓名、名冊上的公務信箱）：

   ```sql
   select public.make_staff('你的個人Email@gmail.com', '秘書長', '你的姓名', '你的公務信箱@mail.mof.gov.tw');
   ```

   角色可填：理事長、秘書長、總幹事、會計、承辦人。
   執行結果的意思：
   - 「已將…設為…，並連結登入帳號…」：成功。
   - 「…還沒有註冊」：回到第 1 步，先註冊。
   - 「名冊上…已連結另一個登入帳號」：這筆名冊被別的帳號連走了。照訊息裡的指令先解除連結，再執行一次。
3. 在會員專區**登出後重新登入**，左側會出現「會員管理、申請審核、活動管理、會費管理」。
4. 之後其他幹部的角色，在「會員管理 → 點該會員 → 幹部角色」指派。只有理事長、秘書長、總幹事能指派。

## 三、匯入名冊，讓會員連結自己的資料

1. 「會員管理 → 匯入名冊」，選 Excel 或 CSV。
   - 標準欄位：姓名、女0男1、服務機關、服務單位、職稱、電子郵件信箱（填公務信箱）。
   - 可另加：公務電話、員工編號、理監事（理事長／常務理事／理事／監事會召集人／常務監事／監事）、會員代表（是）。
2. 會員用個人 Email 註冊、登入後，會進到「連結會員資料」。有兩種連結方式：
   - **認領碼（建議，最快）**：幹部在「會員管理」的「帳號」篩選選「未註冊」，勾選要發碼的會員 →「產生認領碼」→「列印紙條」或「匯出 Excel」，再當面或私訊交給本人。會員輸入後立即連結。認領碼 30 天有效、用一次就失效，**不要貼在群組裡**。
   - **連結申請**：會員沒有認領碼時，填姓名、機關、公務信箱送出。幹部到「申請審核 → 帳號連結」核對資料：系統會預選名冊上對應的人，核准前還會再請你確認一次是不是同一人。
   - 系統**不會**因為註冊 Email 和名冊上的信箱一樣就自動連結。名冊上的公務信箱收不到外部信，無法證明是本人。
3. 名冊上已經有的人，不要走「入會申請」。入會申請填的公務信箱如果名冊上已經有，系統會擋下核准，並提示改用帳號連結。這時按「退回」，原因欄已預填好要請申請人改用「連結會員資料」。
4. 幹部那幾筆（有幹部角色的人）只有理事長、秘書長、總幹事能發認領碼、核准連結、修改會籍或 Email。
5. 連錯人或會員換了個人 Email：理事長、秘書長或總幹事在「會員管理 → 點該會員 → 解除帳號連結」，再重新發認領碼。

## 四、權限規則（資料庫層級，網頁被改也繞不過）

| 誰 | 看得到 | 能做 |
|---|---|---|
| 未登入 | 什麼都看不到 | 只能註冊、登入 |
| 已註冊、尚未連結 | 自己的連結申請、入會申請 | 輸入認領碼、送連結申請、線上申請入會 |
| 一般會員 | 只有自己的會員資料、報名、繳費紀錄 | 改自己的服務機關、單位、職稱、電話、性別；報名或取消活動（可選葷素） |
| 幹部（理事長、秘書長、總幹事、會計、承辦人） | 全體資料 | 會員管理（含產生認領碼）、申請審核、活動管理、會費管理 |
| 理事長、秘書長、總幹事 | 同上 | 另外可以指派幹部角色、解除帳號連結、刪除會員 |

- 理監事欄位只能是「理事」或「監事」其中之一，資料庫會擋下兩者並存。
- 「會員代表」是另外一個勾選，可以和理事或監事並存。
- 帳號連結只能透過認領碼、核准連結、核准入會、`make_staff` 這幾個管道。即使是幹部，也不能直接修改資料表來把別人的名冊連到自己的帳號。
- 活動名額由資料庫判斷：會員自己報名、幹部代為報名都一樣，額滿自動列候補，不會超收。

## 五、平常維護

- Supabase 免費方案的專案**一週沒有人使用會自動暫停**；到 Supabase 網站按「Restore」就會恢復，資料不會遺失。正式使用後，每週都會有人登入，通常不會遇到。
- 備份：Supabase 左側「Table Editor」可以把資料表匯出 CSV；也可以在「會員管理」匯出名冊。
- 會員忘記密碼：請他在登入畫面按「忘記密碼」，系統會寄重設信。前提是第一節第 5 步的寄信服務已經設定好。
- 名冊超過 1000 人也沒問題：網頁會分批讀取。Supabase 的「Max rows」設定（Project Settings → Data API）保持預設即可。
- 程式更新時，把最新版 `線上系統/資料庫結構.sql` 全文貼到 SQL Editor 執行一次，既有資料會保留。
