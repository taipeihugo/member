# 會員專區（線上系統）設定說明

會員專區網址：`https://taipeihugo.github.io/member/portal/`（官網選單的「會員專區」）。
網頁放在 GitHub Pages；帳號與資料存在 **Supabase**（雲端資料庫，免費方案即可）。

> 會員個資會存在 Supabase 的機房（建議選東京或新加坡）。正式使用前，請先向機關人事或政風單位確認可以這樣做。

## 一、建立 Supabase 專案（約 10 分鐘，只做一次）

1. 到 https://supabase.com 註冊（可用 GitHub 帳號登入）→「New project」。
   - Name：`association`（隨意）
   - Database Password：設一個強密碼，**自己保存好**
   - Region：**Northeast Asia (Tokyo)** 或 Southeast Asia (Singapore)
2. 建好後，左側選單「SQL Editor」→「New query」→ 把 `線上系統/資料庫結構.sql` 全文貼上 → 按「Run」。看到 Success 就完成。
   之後程式更新時，再貼一次最新版全文執行即可，既有資料會保留。
3. 左側「Authentication」→「URL Configuration」：
   - Site URL 填：`https://taipeihugo.github.io/member/portal/`
   - Redirect URLs 加一筆：`https://taipeihugo.github.io/member/portal/`
4. 「Authentication」→「Sign In / Providers」→ Email：確認 **Confirm email** 是開啟的，而且**不要關掉**。
   關掉之後，任何人都能用別人的 Email 註冊，系統無法確認帳號是不是本人的。
5. **設定寄信服務（一定要做，否則會員收不到驗證信）**
   Supabase 內建的寄信服務**只會寄給 Supabase 專案團隊成員的信箱**，而且每小時只能寄 2 封左右。
   不設定的話，同仁用 Gmail 註冊時，畫面會出現「協會尚未完成寄信設定」，忘記密碼也收不到信。
   - 到「Authentication」→「Emails」→「SMTP Settings」（舊版介面在 Project Settings → Authentication → SMTP），開啟 **Enable Custom SMTP**。
   - 最簡單的做法：用協會專用的 Gmail 帳號寄信。
     1. 該 Gmail 帳號要先開啟「兩步驟驗證」，再到 Google 帳戶 → 安全性 →「應用程式密碼」，產生一組 16 碼密碼。
     2. 在 SMTP Settings 填入：
        - Host：`smtp.gmail.com`
        - Port：`587`
        - Username：這個 Gmail 地址
        - Password：上一步的 16 碼應用程式密碼
        - Sender email：同一個 Gmail 地址
        - Sender name：`財政部公務人員協會`
     3. Gmail 一天大約可以寄 500 封，協會規模夠用。會員多、或想用協會網域寄信時，可以改用其他寄信服務（例如 Brevo、Resend 的免費方案），依該服務提供的 SMTP 設定填寫。
   - 設好後到「Authentication」→「Rate Limits」，把 **Rate limit for sending emails** 調高，例如每小時 100 封。推廣期間很多人同時註冊，太低的話後面的人會看到「寄信次數已達上限」。
   - **測試**：用一個**不是** Supabase 團隊成員的 Gmail 到會員專區註冊，確認收得到驗證信。
6. 複製兩個值：
   - **Project URL**（像 `https://abcdefgh.supabase.co`）：左側「Project Settings」→「Data API」，或按頁面上方的「Connect」。
   - **Publishable key**（`sb_publishable_` 開頭）：「Project Settings」→「API Keys」→「Publishable and secret API keys」。
     舊專案也可以改用「Legacy API Keys」頁籤裡的 **anon public** 金鑰（很長的一串），兩種都能用。

   把這兩個值交給開發者，填進 `官網/portal/連線設定.js`；也可以自己在 GitHub 網頁上編輯這個檔案。
   公開金鑰（publishable key／anon key）本身沒有讀取權限，放在公開網站上是正常的；資料由資料庫的權限規則保護。
   **同一頁的 Secret key（`sb_secret_` 開頭）和舊版的 `service_role` 金鑰絕對不能給任何人，也不能放在網站上。**

## 二、指定第一位幹部（只做一次）

1. 先準備一個登入帳號（任選一種）：
   - 到會員專區「註冊帳號」，用收得到信的個人 Email，再到信箱點驗證連結；或
   - 收不到信、還沒設定寄信服務、或是測試用的假帳號（例如 `moftest@mof.gov.tw`）：在 Supabase「Authentication」→「Users」→「Add user」→「Create new user」，填 Email 和密碼，**勾選 Auto Confirm User**，按「Create user」。這樣不用收信就能登入。
2. 回到 Supabase 的「SQL Editor」，執行下面這行（依序是：登入 Email、角色、姓名、名冊上的公務信箱）：

   ```sql
   select public.make_staff('你的登入Email', '秘書長', '你的姓名', '你的公務信箱@mail.mof.gov.tw');
   ```

   角色要是「系統設定」裡有的角色（預設：理事長、秘書長、總幹事、會計、承辦人）。
   執行結果的意思：
   - 「已將…設為…，並連結登入帳號…」：成功。
   - 「…還沒有註冊」：回到第 1 步，先準備登入帳號。
   - 「名冊上…已連結另一個登入帳號」：這筆名冊被別的帳號連走了。照訊息裡的指令先解除連結，再執行一次。
3. 在會員專區**登出後重新登入**，左側會出現「會員管理、申請審核、活動管理、會費管理、系統設定」。
4. 之後就都在網頁上操作，不用再進 Supabase：
   - 其他幹部：「會員管理 → 點該會員 → 幹部角色」指派。只有**具管理權限**的幹部（預設是理事長、秘書長、總幹事）能指派。
   - 要指派（或變更幹部角色）的會員如果已經有登入帳號，這個帳號必須經具管理權限的幹部建立或核對過。由會計、承辦人核准連結的，或姓名、Email、員工編號是會計、承辦人新增或修改的，系統會擋下：請在「會員管理 → 點該會員」看他的**登入帳號**，向本人確認無誤後勾選「已向本人核對」並儲存，就能在同一次儲存指派。這是為了防止有人先把自己的分身帳號連到日後會當幹部的會員。取消幹部角色不受限制。

## 三、系統設定（幹部角色、理監事職稱）

具管理權限的幹部，左側有「系統設定」：

- **幹部角色**：新增（例如「副秘書長」）、刪除、用 ↑ ↓ 調整選單順序。勾選「管理權限」的角色可以指派幹部角色、建立登入帳號、重設密碼、解除帳號連結、刪除會員、修改系統設定；沒勾的角色（例如會計、承辦人）可以看全體名冊、處理申請、活動與會費。
- **理監事職稱**：新增（例如「候補理事」、「副理事長」）、刪除、調整順序。每個職稱要選「屬於理事」或「屬於監事」；一位會員只能有一個職稱，所以理事、監事互斥。「會員代表」在會員資料另外勾選，可與任一職稱並存。
- 還有會員在用的角色或職稱不能刪除（刪除鈕是灰的），請先到「會員管理」改掉。
- 系統會擋下「改完就沒有任何人具管理權限」的操作（取消角色的管理權限、唯一的管理者把自己卸任、停權、解除帳號連結或刪除），避免把自己鎖在外面。萬一真的鎖住，可以在 SQL Editor 用 `make_staff` 重新指定。

## 四、匯入名冊、替會員建立登入帳號

1. 「會員管理 → 匯入名冊」，選 Excel 或 CSV。
   - 標準欄位：姓名、女0男1、服務機關、服務單位、職稱、電子郵件信箱（填公務信箱）。
   - 可另加：公務電話、員工編號、理監事（填「系統設定」裡有的職稱，例如理事長、常務理事、理事、監事會召集人、常務監事、監事）、會員代表（是）。
   - 怎麼判斷是名冊上的同一人（是就更新，不是就新增）：Email 相同；或員工編號（不分大小寫）、姓名都相同；或姓名＋服務機關相同，而且名冊上只有一位、Email 與員工編號沒有矛盾。
     同名同機關但 Email 或員工編號不同，視為不同人。無法判斷的列會在匯入前列出並略過，請補上 Email 或員工編號再匯入。
   - 檔案裡同一人出現好幾列（Email 相同，或員工編號＋姓名相同）會先合併；合併後彼此矛盾（例如 Email 相同但員工編號不同、或姓名不同）時，這幾列都略過並說明。
   - 同一人有調職前後的列（機關不同）時，各列的「姓名＋服務機關」都會拿來比對名冊。
   - 對到哪一位、要新增還是更新，和列的先後順序無關；合併時各欄位以後面的列為準。
   - 更新時，空白的儲存格不會清掉名冊上原有的資料。
   - 匯入到一半網路中斷時會停下來；等網路恢復、重新整理後，再匯入同一個檔案即可，已匯入的人會更新，不會重複。
     但檔案沒有「服務機關」欄時，沒有 Email、員工編號的人無法比對，再匯入會重複新增（匯入前的預覽會提醒）。
   - Email 是別人的（姓名、員工編號卻指向名冊上另一位，多半是填錯）時，該列會略過並說明，不會覆蓋別人的資料。
2. **替會員建立登入帳號（建議，最快）**：「會員管理 → 點該會員 →『建立登入帳號』」，填登入 Email 和初始密碼，按「建立帳號」。
   - 不寄驗證信，建立後馬上可以登入；公務信箱收不到外部信、或測試用的假帳號（例如 `moftest@mof.gov.tw`）都可以用。
   - Email 請填**本人親自提供**的（對話框不會預先帶入名冊上的 Email，避免名冊被改過）。
   - 把 Email 和密碼交給本人（當面或私訊，不要貼在群組），請他登入後到「我的資料 → 修改密碼」自己改。
   - 這個 Email 如果有人註冊過但**還沒完成驗證**（例如註冊了卻收不到驗證信），會直接完成驗證、改成你設定的密碼並連結。已經驗證過的帳號不能這樣接管，請本人登入後送「連結申請」。
   - 忘記密碼又收不到重設信：「會員管理 → 點該會員 →『重設密碼』」。重設後這個帳號原本的登入全部失效。不能替其他具管理權限的幹部重設（他們自己用「修改密碼」或「忘記密碼」）。
   - 萬一按「建立帳號」出現權限錯誤（Supabase 日後調整了 auth 的權限）：改用 Supabase「Authentication → Users → Add user」（勾 Auto Confirm User）建立帳號，再請本人登入後送「連結申請」，或在 SQL Editor 用 `make_staff` 連結。
3. **會員自己註冊**：用個人 Email 註冊、驗證後登入，會進到「連結會員資料」，填姓名、機關、公務信箱送出「連結申請」。幹部到「申請審核 → 帳號連結」核對：系統會預選名冊上對應的人，核准前還會再請你確認一次是不是同一人。
   - 系統**不會**因為註冊 Email 和名冊上的信箱一樣就自動連結。名冊上的公務信箱收不到外部信，無法證明是本人。
4. 名冊上已經有的人，不要走「入會申請」。入會申請填的公務信箱如果名冊上已經有，系統會擋下核准。這時按「退回」，原因欄已預填好，請申請人改送連結申請（或直接替那位會員建立登入帳號）。
5. 幹部那幾筆（有幹部角色的人）只有具管理權限的幹部能建立帳號、核准連結、修改會籍或 Email。
6. 連錯人或會員換了登入 Email：具管理權限的幹部在「會員管理 → 點該會員 → 解除帳號連結」，再替他建立登入帳號。

## 五、權限規則（資料庫層級，網頁被改也繞不過）

| 誰 | 看得到 | 能做 |
|---|---|---|
| 未登入 | 什麼都看不到 | 只能註冊、登入 |
| 已註冊、尚未連結 | 自己的連結申請、入會申請 | 送連結申請、線上申請入會 |
| 一般會員 | 只有自己的會員資料、報名、繳費紀錄 | 改自己的服務機關、單位、職稱、電話、性別；改自己的密碼；報名或取消活動（可選葷素） |
| 幹部（所有幹部角色） | 全體資料 | 會員管理、申請審核、活動管理、會費管理 |
| 具管理權限的幹部（預設：理事長、秘書長、總幹事） | 同上，另外看得到會員的登入帳號 | 另外可以指派幹部角色、建立登入帳號、重設密碼、解除帳號連結、刪除會員、系統設定 |

- 理監事職稱只能有一個，依「系統設定」決定是理事或監事，所以兩者互斥；資料庫會擋下清單外的職稱與角色。
- 「會員代表」是另外一個勾選，可以和理事或監事並存。
- 帳號連結只能透過建立登入帳號、核准連結、核准入會、`make_staff` 這幾個管道。即使是幹部，也不能直接修改資料表來把別人的名冊連到自己的帳號。
- 密碼一律以 bcrypt 雜湊儲存（與 Supabase 登入相同），資料庫裡沒有明碼。
- 活動名額由資料庫判斷：會員自己報名、幹部代為報名都一樣，額滿自動列候補，不會超收。

## 六、平常維護

- Supabase 免費方案的專案**一週沒有人使用會自動暫停**；到 Supabase 網站按「Restore」就會恢復，資料不會遺失。正式使用後，每週都會有人登入，通常不會遇到。
- 備份：Supabase 左側「Table Editor」可以把資料表匯出 CSV；也可以在「會員管理」匯出名冊。
- 會員忘記密碼：請他在登入畫面按「忘記密碼」，系統會寄重設信（前提是第一節第 5 步的寄信服務已經設定好）；收不到信的帳號，由具管理權限的幹部在「會員管理」替他「重設密碼」。
- 名冊、報名、繳費紀錄超過 1000 筆時，網頁會分批讀取。Supabase 的「Max rows」設定（Project Settings → Data API）保持預設即可。
- 程式更新時，把最新版 `線上系統/資料庫結構.sql` 全文貼到 SQL Editor 執行一次，既有資料會保留；你在「系統設定」增刪的角色、職稱也會保留。
  - v2.1 起移除「認領碼」，改由具管理權限的幹部直接「建立登入帳號」。
